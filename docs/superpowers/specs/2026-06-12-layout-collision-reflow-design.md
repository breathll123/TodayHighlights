# 布局碰撞自动下移设计

## 目标

修复后台布局编辑器的碰撞行为：把已有方块拖到顶部或其他已占用位置时，被碰撞的方块应自动向下移动，不得覆盖，也不得把拖动方块回弹到原位置。

本次同时统一缩放行为。方块放大后如果占用其他方块的位置，其他方块应按网格算法自动下移。

## 根因

当前 `CanvasEditor` 在拖拽或缩放结束后，只使用 `newItem` 构造被操作方块，再与旧的 `blocks` 坐标做碰撞检查。只要目标位置已有方块，应用层就回退旧布局。

`react-grid-layout` 2.2.3 在 `noCompactor` 模式下会下推直接碰撞的方块，但不会可靠解决连续碰撞链。例如三个同列方块位于 `y=0、1、2`，把第三个拖到 `y=0` 后，库可能把前两个方块都放到 `y=1`。因此不能直接持久化库回调的完整 `layout`，否则仍可能重叠。

根因是当前系统只有“阻挡回弹”逻辑，没有一套保证最终无重叠的连续下推算法。

## 交互规则

采用插入式重排：

- 拖动方块进入已占用区域时，保留拖动方块的新位置。
- 被碰撞方块及其后续连锁碰撞方块自动向下移动。
- 不允许最终布局存在重叠。
- 不启用全局垂直压缩，未参与碰撞的原有留白保持不变。
- 方块仍不得超出四列画布的左右边界。
- 缩放产生碰撞时采用同一套自动下移规则。
- 不再显示“该位置已有其他组件”的阻挡提示。

## 实现边界

### `grid-utils.ts`

新增三个纯函数：

1. `reflowBlocks(blocks, activeId, targetRect)`：

- 将被操作方块固定在 `targetRect`。
- 其余方块按原始 `(grid_y, grid_x, id)` 排序。
- 每个方块先保留原位置。
- 如果与已放置方块碰撞，将其 `grid_y` 移到所有当前碰撞方块底边的最大值。
- 重复检测，直到该方块不再与任何已放置方块重叠。
- 保持 `grid_x` 和尺寸不变，因此不相关列和原有留白不会被压缩。
- 返回最终保证无重叠的完整 `Block[]`。

2. `insertBlockAtTop(blocks, colSpan, rowSpan)`：

- 在 `(0, 0)` 创建不带数据库 ID 的占位矩形。
- 以该矩形为固定锚点，复用相同的连续下推算法。
- 返回已有方块的新布局以及新方块坐标。

3. `changedLayoutBlocks(previous, next)`：

- 只比较 `grid_x`、`grid_y`、`col_span`、`row_span`。
- 返回真正需要持久化的方块。

这些纯函数负责提供稳定、可单元测试的重排和差异计算，不在组件或页面中重复碰撞算法。

### `CanvasEditor.tsx`

拖拽和缩放停止时：

1. 从 `newItem` 读取被操作方块的目标位置和尺寸。
2. 调用 `reflowBlocks` 生成下一版 `Block[]`。
3. 校验目标方块没有越过四列边界。
4. 调用 `onLayoutChange(nextBlocks)`。

保留 `noCompactor`，避免组件内部把未参与碰撞的方块强制向顶部压缩。最终业务坐标以 `reflowBlocks` 的结果为准。

### `AdminLayoutPage.tsx`

布局保存只提交真正变化的方块，比较：

- `grid_x`
- `grid_y`
- `col_span`
- `row_span`

使用 `Promise.all` 保存同一次重排产生的所有变化。全部成功后再刷新查询；任意失败时显示错误并刷新服务端状态，避免画布长期保留部分保存的坐标。

新增方块继续默认插入顶部，但改用 `insertBlockAtTop` 完成连续下推，避免当前只移动首层碰撞方块、后续方块仍可能重叠的问题。先保存已有方块的新位置，再创建新方块；任何请求失败都刷新服务端状态并提示用户。

## 测试

新增网格工具测试，覆盖：

- 把底部方块拖到 `y=0` 后，顶部方块被推到下一行。
- 连锁碰撞时多个方块依次下移且最终无重叠。
- 不相关列中的方块保持原坐标。
- 缩放操作固定新尺寸，并连续下推所有受影响方块。
- 未变化方块不会进入持久化更新集合。

组件测试覆盖 `CanvasEditor` 使用 `newItem` 的目标位置调用连续下推函数，而不是碰撞后回退旧布局。

最后运行前端完整测试和构建，并在后台布局页面手动验证拖拽与缩放。

## 非目标

- 不改前台公开页面的 CSS Grid 排版。
- 不改变四列网格和尺寸预设。
- 不增加撤销、批量选择或自动保存状态提示。
- 不启用全局紧凑排列。
