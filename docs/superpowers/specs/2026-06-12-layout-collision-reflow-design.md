# 布局碰撞自动下移设计

## 目标

修复后台布局编辑器的碰撞行为：把已有方块拖到顶部或其他已占用位置时，被碰撞的方块应自动向下移动，不得覆盖，也不得把拖动方块回弹到原位置。

本次同时统一缩放行为。方块放大后如果占用其他方块的位置，其他方块应按网格算法自动下移。

## 根因

`react-grid-layout` 2.2.3 在 `onDragStop` 和 `onResizeStop` 中已经返回完成碰撞处理后的完整 `layout`。当前 `CanvasEditor` 忽略该参数，只使用 `newItem` 构造被操作方块，再与旧的 `blocks` 坐标做碰撞检查。

因此会发生：

1. 网格库已经把被碰撞方块向下移动。
2. 应用层没有接收这些新坐标。
3. 应用层仍然根据旧坐标判断为碰撞。
4. 最终调用旧布局并显示“该位置已有其他组件”，导致回弹或视觉覆盖。

## 交互规则

采用插入式重排：

- 拖动方块进入已占用区域时，保留拖动方块的新位置。
- 被碰撞方块及其后续连锁碰撞方块自动向下移动。
- 不允许最终布局存在重叠。
- 不启用全局垂直压缩，未参与碰撞的原有留白保持不变。
- 方块仍不得超出四列画布的左右边界。
- 缩放产生碰撞时采用同一套自动下移规则。
- 不再显示“该位置已有其他组件”的阻挡提示。

## 实现边界

### `grid-utils.ts`

新增两个纯函数：

1. 将 `react-grid-layout` 返回的 `Layout` 映射回业务 `Block[]`：

- 按字符串 ID 找到对应方块。
- 同步 `grid_x`、`grid_y`、`col_span`、`row_span`。
- 忽略未知 layout item。
- 保持方块其他字段不变。

2. 为新方块计算顶部插入布局：

- 将已有方块转换为 `Layout`。
- 添加一个临时 layout item。
- 使用 `react-grid-layout` 导出的 `moveElement`，以 `compactType=null` 将临时方块移动到 `(0, 0)`。
- 接收库计算出的完整碰撞链结果。
- 将已有方块的新坐标映射回业务数据。

这些纯函数负责提供稳定、可单元测试的业务映射和重排，不在组件或页面中重复碰撞算法。

### `CanvasEditor.tsx`

拖拽和缩放停止时：

1. 接收回调的完整 `layout`。
2. 使用映射函数生成下一版 `Block[]`。
3. 校验最终布局没有重叠且没有越界。
4. 调用 `onLayoutChange(nextBlocks)`。

保留 `noCompactor`。该设置不会阻止碰撞下移，只会避免操作结束后将所有方块强制向顶部压缩。

### `AdminLayoutPage.tsx`

布局保存只提交真正变化的方块，比较：

- `grid_x`
- `grid_y`
- `col_span`
- `row_span`

使用 `Promise.all` 保存同一次重排产生的所有变化。全部成功后再刷新查询；任意失败时显示错误并刷新服务端状态，避免画布长期保留部分保存的坐标。

新增方块继续默认插入顶部，但改用上述 `moveElement` 重排函数，避免当前只移动首层碰撞方块、后续方块仍可能重叠的问题。先保存已有方块的新位置，再创建新方块；任何请求失败都刷新服务端状态并提示用户。

## 测试

新增网格工具测试，覆盖：

- 把底部方块拖到 `y=0` 后，顶部方块被推到下一行。
- 连锁碰撞时多个方块依次下移且最终无重叠。
- 不相关列中的方块保持原坐标。
- 缩放后的完整 layout 正确同步尺寸与位置。
- 未变化方块不会进入持久化更新集合。

组件测试覆盖 `CanvasEditor` 使用回调的完整 layout，而不是只保存 `newItem`。

最后运行前端完整测试和构建，并在后台布局页面手动验证拖拽与缩放。

## 非目标

- 不改前台公开页面的 CSS Grid 排版。
- 不改变四列网格和尺寸预设。
- 不增加撤销、批量选择或自动保存状态提示。
- 不启用全局紧凑排列。
